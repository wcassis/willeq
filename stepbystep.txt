  Phase 2: Main Loop (application.cpp:386)

  The main loop runs on the main thread while the loading thread renders the progress bar:

  Each iteration:
  1. processNetworkEvents() → m_eqClient->TickNetwork() — pumps login/world/zone connection managers
  2. Input processing at ~60fps (disabled when graphics handle input)
  3. updateGameState() → UpdateMovement(), syncGameStateFromClient(), updateLoadingProgress()
  4. render() → UpdateGraphics() — but returns early when loading thread is active (m_loading_thread != null)
  5. Check quit request
  6. sleep_for(1ms) (unconditional)

  Phase 3: Login Server (eq.cpp:965-1370)

  All driven by TickNetwork() → LoginOnPacketRecv():

  3a: Connect (LOGIN_CONNECTING)

  - UDP connection established → LoginOnStatusChangeReconnectEnabled() fires
  - Sends SessionReady packet

  3b: Authenticate (LOGIN_AUTHENTICATING)

  - Server sends ChatMessage → client sends Login (encrypted user/pass)
  - Server sends LoginAccepted → extracts session key, DBID

  3d: World Redirect

  - Server sends PlayEverquestResponse → extracts world server IP address

  Phase 5: Zone Server (eq.cpp:1815-7175)

  5a: Connect (ZONE_CONNECTING)

  - Initializes InventoryManager + sets up inventory callbacks
  - Initializes SpellManager + loads spell database from EQ client files
  - Creates BuffManager
  - Creates DaybreakConnectionManager (CRC validation skipped), connects to zone server
  - On connected: sends StreamIdentify, AckPacket, ZoneEntry

  5b: Receive Player Profile (ZONE_RECEIVING_PROFILE)

  - Server sends PlayerProfile → extracts player stats (HP, mana, level, class, race, skills, spells, AAs, inventory, buffs, bind points, position, zone ID, etc.)

  5c: Zone Request Phase (ZONE_REQUEST_PHASE)

  - Server sends a burst of zone setup data:
    - NewZone — zone geometry params, fog settings, sky type, gravity, safe coords
    - ZoneSpawns (ZONE_RECEIVING_SPAWNS) — all entities in zone (can be multiple packets)
    - DoorSpawns — all door objects
    - SendAATable, RespondAA — AA data
    - TributeInfo, SendGuildTributes — tribute data
    - Weather, ZonePoints, SpawnAppearance, etc.

  5d: Check Completion (CheckZoneRequestPhaseComplete())

  - Waits until ALL required packets received: NewZone + at least one AA table + tribute + guild tribute
  - Sends ReqClientSpawn → triggers server to send remaining spawn data

  5e: Player Spawn Phase (ZONE_PLAYER_READY → ZONE_AWAITING_CONFIRM)

  - Server sends GuildMOTD (last packet in SendZoneInPackets)
  - Client sends SetServerFilter + ClientReady
  - Waits for first ClientUpdate with player's own spawn ID

  5f: Game State Complete

  - First own ClientUpdate received → confirms player position
  - StartUpdateLoop() — begins periodic position/movement updates
  - Sets renderer networkReady = true, expectedEntityCount
  - Calls OnGameStateComplete() (eq.cpp:1106)
