PRIMARY evidence: numeric MaterialType trace (not pixel stills)
-----------------------------------------------------------------
Live in-frame stills of a specific zombie's masked leg/chest texture proved
unreliable to pin down in this session (zombies wander from their spawn2
coordinates; #goto/moveto GM-teleport attempts repeatedly landed the camera
in open space with no target in frame — see "stills" section below for what
WAS captured). Rather than keep spending session budget chasing exact
framing, this unit falls back to the SAME numeric-trace technique P21 used
for its own entity-side evidence (P21 Review, "Entity (latent) case"): two
temporary, uncommitted LOG_INFO diagnostics (one in
RaceModelLoader::buildMeshFromGeometry, mesh_building.cpp; one right after
EntityRenderer::applyAlphaTestMaterialType()'s call site in
entity_renderer.cpp's createEntity path), both fully reverted (verified via
`git diff` showing no trace) before the final build/verification pass and
commit.

Trace, live befallen zone-in (all 3 test-zone ground-truth masked textures
that are actually befallen-resident: zomch0001.bmp, zomlg0001.bmp; per-race
unmasked siblings zomch0002-5.bmp/zomlg0002.bmp shown for contrast):

| texture         | isMasked (WLD, post-fix) | MaterialType assigned by mesh_building.cpp |
|-----------------|--------------------------|---------------------------------------------|
| zomch0001.bmp   | true                     | 14 (EMT_TRANSPARENT_ALPHA_CHANNEL_REF marker) |
| zomlg0001.bmp   | true                     | 14 (EMT_TRANSPARENT_ALPHA_CHANNEL_REF marker) |
| zomch0002-5.bmp | false                    | 0 (EMT_SOLID, unchanged)                     |
| zomlg0002.bmp   | false                    | 0 (EMT_SOLID, unchanged)                     |

Downstream, EntityRenderer::createEntity's material-assignment loop (the
EMT_TRANSPARENT_ALPHA_CHANNEL_REF branch, entity_renderer.cpp ~line 636)
converts marker 14 into the compiled GLES2 RGBA alpha-test shader:

| stage                                         | MaterialType | meaning |
|------------------------------------------------|--------------|---------|
| mesh_building.cpp (masked, before entity_renderer) | 14        | EMT_TRANSPARENT_ALPHA_CHANNEL_REF — fixed-function marker, not a compiled GLES2 program |
| entity_renderer.cpp (after applyAlphaTestMaterialType) | 258   | compiled RGBA alpha-test shader (alphaTestRGBA) — SAME numeric ID P21's door evidence table documented for the identical shader |

This is decisive: before this unit, mesh_building.cpp hardcoded EMT_SOLID
(0) unconditionally, so masked entity materials NEVER reached
applyAlphaTestMaterialType() at all (P21's own audit, confirmed again by
re-running this trace against the pre-fix code — isMasked always false,
MaterialType always 0). After this unit, the two masked befallen zombie
textures are correctly classified, marked, and routed to the compiled
alpha-test shader — P21's dead code is now live.

Root-cause note (why the fix needed a 4th file beyond the plan's named
territory): the FIRST version of this fix (mesh_building.cpp alone) traced
isMasked=false for zomlg0001.bmp/zomch0001.bmp despite WLD ground truth
being masked=true. Root cause: RaceModelLoader builds character meshes from
a COMBINED geometry (geometry_combiner.cpp's combineCharacterParts /
combineCharacterPartsWithTransforms / combineCharacterPartsRaw, merging
per-body-part DMSPRITEDEF geometries into one ZoneGeometry for the animator)
— all three combiner functions copied textureNames and textureInvisible
into the merged materialData but silently DROPPED textureMasked entirely,
so every combined character geometry's textureMasked() always came back
empty regardless of source WLD data. This is upstream of mesh_building.cpp
and race_model_loader.cpp, in the same data-flow path (the geometry object
mesh_building.cpp directly consumes) — without this fix the unit's stated
goal (masked entity textures actually render masked) is unreachable no
matter what mesh_building.cpp does. Flagged as a deviation in the plan's
Review (in-territory by necessity, not scope creep for its own sake).

Ground-truth WLD scan tool
-----------------------------
A throwaway diagnostic (not committed, mirrors P21's own throwaway WLD
scanner) built against wld_loader.cpp/pfs.cpp using
WldLoader::getGeometries()/textureMasked() directly — the same ground-truth
signal zone_geometry.cpp/mesh_building.cpp consult — enumerated all
Fragment 0x30 TransparentMasked materials in befallen_chr.wld,
qeynos2_chr.wld, gfaydark_chr.wld, and global_chr.wld. A second throwaway
tool (EQE1Loader-based) queried the deployed /mnt/projects/EverQuest_ETC1/
*.eqe1 archives for each masked texture's `hasAlpha`/companion-alpha
presence. See the plan Review's ground-truth table for full results.
