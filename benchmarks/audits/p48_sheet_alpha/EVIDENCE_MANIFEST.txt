P48 -- composite-sheet alpha support: evidence manifest
=========================================================

Builder change (tools/entity_composite_builder.cpp)
----------------------------------------------------
- BodyPartTexture/PlacedTexture gained an `isMasked` field, set from
  `part->textureMasked()` (WLD Fragment 0x30 TransparentMasked), the SAME
  parallel-array signal mesh_building.cpp/race_model_loader.cpp already
  consult for the non-composite path (P37).
- decodeBMP()/decodeTextureFromArchive() gained an `applyPaletteMask`
  parameter (default false -- byte-identical to pre-P48 for every call site
  that doesn't pass true). When true, 8bpp palette index 0 decodes to
  alpha=0 (mirrors tools/eqe1_builder.cpp's existing zone-texture
  convention); only masked placements request it.
- writeEQE1() gained a `hasAlpha` parameter (default false, same
  byte-identical guarantee). When a sheet has >=1 masked placement, the main
  EQE1 entry becomes EQE1_TYPE_ETC1_RGBA/hasAlpha=1 and a second index entry
  named "{baseName}_alpha" (grayscale R=G=B=alpha ETC1) immediately follows
  it -- the exact layout ConstrainedTextureCache's existing ETC1 upload path
  (constrained_texture_cache.cpp, unmodified by this unit) already knows how
  to find and bind on texture unit 1 for ANY EQE1 entry, zone or composite.
- The composite sheet JSON gained a `"hasAlpha"` boolean key, read at
  runtime by CompositeTextureData::hasAlpha (composite_texture_data.h,
  defaults false when the key is absent -- safe for sheets built by a
  pre-P48 builder).

Byte-identity verification (unmasked sheets)
---------------------------------------------
27 of the 86 regenerated sheets got a real alpha companion (masked);
the other 59 are unmasked. Of those 59: 56 are byte-identical (BMP+EQE1
md5) to the currently-deployed live sheets; the JSON differs ONLY by the
added "hasAlpha": false key (verified by diffing both JSONs with that key
stripped -- zero remaining diff). The remaining 3 (min_hs_def_0_0,
gnn_hs_def_0_1, gnn_hs_def_0_3) differ from live for reasons that PREDATE
this unit: rebuilding them with the unmodified pre-P48 entity_composite_
builder.cpp (git stash isolation, reproduced independently) produces the
SAME byte-level diff against live -- i.e. those 3 sheets were already stale
relative to the current tree before this unit touched anything (unrelated
drift, not introduced by P48). Isolation method: `git stash` the 4 P48
source files, rebuild entity_composite_builder, regenerate the affected
zone, `cmp` against live, `git stash pop`, rebuild again.

Eligibility gate (race_model_loader.cpp)
------------------------------------------
preloadModelData()'s composite lookup now checks
`compositeHasMaskedTexture && !compositeData->hasAlpha` (was: blanket
`compositeHasMaskedTexture`). Two new LOG_INFO lines:
  "composite EXCLUDED ... this sheet has no alpha companion (P37/P48 gate)"
  "composite ADMITTED ... this sheet carries an alpha companion (P48)"
Confirmed both fire correctly: pre-deploy (old live sheets, no alpha),
ZOM/race70 logged EXCLUDED; post-deploy (new sheets with alpha), the SAME
race logs ADMITTED. See "Pre/post deploy comparison" below.

Rendering (mesh_building.cpp)
--------------------------------
buildCompositeMeshFromGeometry() now sets
`compositeData.hasAlpha ? EMT_TRANSPARENT_ALPHA_CHANNEL_REF : EMT_SOLID`
(both buffer-creation sites, including the >65535-vertex overflow branch),
replacing the unconditional EMT_SOLID. No entity_renderer.cpp call-site
change was needed: its existing generic per-buffer promotion loop
(createEntity(), "if MaterialType == EMT_TRANSPARENT_ALPHA_CHANNEL_REF,
applyAlphaTestMaterialType()") already applies uniformly to composite and
multi-buffer mesh buffers alike -- confirmed by reading the call site, not
assumed. The benchmark's own mirror of that loop
(zone_bench_loader.cpp's applyEntityShaderMaterialPromotion(), from
P46/P46b) is equally generic and needed no changes either.
