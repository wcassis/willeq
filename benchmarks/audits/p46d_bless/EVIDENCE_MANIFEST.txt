P46d — Round-5 neutral bless pair: RGBA mode, promotion OFF both legs
======================================================================

Purpose: demonstrate the ConstrainedTextureCache cache-key fix (P46d) by
capturing the pair P46c set out to capture but could not (RGBA-mode
alpha-test discard never fired due to a cache-key collision poisoning the
masked variant with an earlier unmasked decode). This pair shows P37
(WLD-masked-material detection) + P46 Part A (runtime palette-index-0
decode) jointly, under neutral instrument lighting (promotion OFF on BOTH
legs, so there is exactly one variable: the mask fix itself).

Binaries
--------
BEFORE = commit fda2e34 (pre-P37, same commit every prior unit in this
         chain has used). Reused wt/slot2/build-preP37/ scratch build:
         gles2_zone_benchmark 14,383,392 bytes / willeq 79,261,280 bytes --
         byte-for-byte match to every prior unit's documented size,
         confirmed non-stub/non-stale. No --no-entity-shader-promotion flag
         exists on this binary (predates P46c) -- it is inherently
         "promotion off" by construction (the flag's entire purpose is
         opting OUT of a promotion step that didn't exist yet at this
         commit), satisfying "promotion OFF both legs" without needing the

         ordering fix). Built fresh: build-gles2/bin/gles2_zone_benchmark

         --no-entity-shader-promotion.
x86 GLES2 (llvmpipe) only via gles2_zone_benchmark. No Pi, no eqemu.

frames 12/26/42, --orbit-radius 8 --orbit-height-offset 6, SKE race 21

Deviations
----------
1. A small (13-44px), non-entity rendering artifact reproducibly appears at
   frame 12 only, at screen coordinates ~(5-7, 497-513), on a distant
   background building/roof silhouette detail -- present even with
   --entities 0 (zero P46d code paths exercised). Root cause not chased
   further (out of this unit's budget): most likely explained by this
   session's shared third_party/irrlicht-gles2-x86 tree being rebuilt
   mid-session (see Review, "build hazards") -- the BEFORE binary
   (build-preP37/) is a frozen artifact from a prior session's Irrlicht
   build, while AFTER was linked against this session's freshly-rebuilt
   tree; a few pixels of rasterization/culling threshold difference on a
   tiny distant detail between two separately-built Irrlicht copies is
   plausible and consistent with the artifact's small size, single-frame
   occurrence, and total independence from any P46d code path. f26/f42 are
   unaffected (AE=0 zone-only) and are the frames this manifest leads on;
   f12 is included in the numeric table for completeness but not treated as
   a clean pair.
2. zone_bench_loader.cpp's own "Pre-load meshes for each race" static loop
   (pre-existing, unrelated to P46) had to be supplemented with a
   production-accurate unconditional preloadModelData() call (this unit's
   benchmark-only fix, see Review) for the RGBA leg to exercise the masked
   decode at all -- without it, T05 (the only call site that ever requests
   applyPaletteMask=true for a race's base body textures) never ran in this
   tool's non-composite invocation, independent of the cache-key fix. Not a
   production change.
