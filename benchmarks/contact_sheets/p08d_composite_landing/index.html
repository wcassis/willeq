P08d: composite entities vs multi-buffer — STATIC evidence (animated evidence retracted)

This replaces ALL prior P08d evidence, original round AND the first retake round. Will identified that every animated shot in the unit shows a malformed/garbled model. Independent verification (orchestrator, two experiments) confirmed the cause is pre-existing in the benchmark's --animate scenegraph path — running the exact same evidence command without --animate renders a correctly-formed, correctly-textured character; running the same command with --animate on a PRE-P08d binary reproduces the identical garbling. P08d did not introduce this. But it means every claim about animation quality made from either P08d evidence round (including the first retake's "pixel-identical once aligned" and "tile-boundary bleed" close-up) was measured on garbled geometry and is VOID — not wrong about composite vs baseline necessarily, but not evidence of anything, because neither side of the comparison was rendering correctly. See the plan Review's "Pre-existing benchmark --animate garbling" section for the full writeup and what this means for a follow-up unit.
This package re-does the composite-vs-baseline quality comparison and the tile-boundary defect check entirely on STATIC models — no --animate anywhere — using the first retake's --composite-scenegraph alignment fix (still the correct vehicle: it renders composite entities through the same default entity draw path as baseline, avoiding the unrelated custom-cull-test benchmark bug that caused the original round's misleading numbers).

Aligned comparison (default orbit, qeynos2, 6 entities, STATIC, seed 42)

Both runs use the SAME procedurally-generated camera path (--dump-path/--path-file, byte-identical trajectory) and the SAME entity placement. Baseline = default entity path (multi-buffer). Composite = --composite-scenegraph (real production composite mesh, same draw path as baseline). Neither run passes --animate.

Result: pixel-identical at every frame checked (0.000% differing pixels, f15/f25/f35 shown; also true at f5/10/20/30/40/45/50/55, checked but not shown). This is the expected "same texels, repacked" outcome for a uniform-variant NPC with no per-slot overrides, now confirmed on correctly-rendered geometry instead of the previously-garbled animated frames.

Close-up (orbit-radius 15 — full character fills a meaningful fraction of the frame)

The default orbit never brings the camera close enough to any entity for a proper close-up (the orbit-fallback camera's radius is fixed by zone geometry, not entity position) — this was the root cause of Will's original "arm shot" complaint, independent of the animation-garbling issue. --orbit-radius 15 (deterministic, same flag both runs) was tuned by inspecting several candidate frames until two gave a genuinely judgeable full-character view.

Result: pixel-identical at both close-up frames (0.000% differing pixels). On static geometry, composite and multi-buffer are visually indistinguishable even at close range.

Tile-boundary defect re-check (orbit-radius 8 — extreme close-up, torso-filling)

The first retake's animated evidence reported a "faint dark patches/bleeding" artifact at composite-sheet tile boundaries, visible in a close-up crop, and attributed it to bilinear-filter texel bleed. That close-up was rendered on garbled animated geometry (see warning above), so the claim is void — this section re-checks it on valid static geometry.

Tight crop on the torso (1400x1000, nearest-neighbor 4x, lossless — no interpolation added by the crop/zoom itself):

Verdict: the tile-boundary defect does NOT reproduce on static geometry. The dark tattoo-like pattern visible on the torso in both crops is real texture content (this NPC's body-paint/tattoo texture), present identically in baseline and composite. The 2.0% full-frame / 7.5% crop "differing pixel" counts are sparse, single-pixel, sub-visible noise (mean channel delta <0.06 out of 255) — consistent with floating-point rounding / anti-aliasing jitter at an oblique close viewing angle, not a coherent defect. Visual inspection of the diff crop (below) shows no tile-edge pattern, no blob, no structure — just scattered single-pixel specks. This changes the prior "known-minor open item" status: on the evidence available now, there is no demonstrated composite-specific rendering defect to report to Will as an open item.
